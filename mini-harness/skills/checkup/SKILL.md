# 커밋 전 점검

이 스킬의 일은 **판단**이다. 세는 일은 이미 스크립트가 했다.

`mh-changes` 가 준 STATUS 라인을 다시 세지 마라. 파일 개수를 확인하려고
`git status` 를 또 부르지 마라. 숫자는 확정된 사실로 받고, 그 위에서 판단만 한다.

## 0. 사실을 받는다

커맨드가 이미 `mh-changes` 출력을 붙여 놓았다. 없으면 직접 부른다:

```bash
# ${CLAUDE_PLUGIN_ROOT} 는 플러그인으로 설치했을 때만 설정된다.
# install.sh 로 심볼릭 링크만 건 경우를 위해 폴백을 둔다.
_MH="${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/skills/checkup/..}/bin/mh-changes"
[ -x "$_MH" ] || _MH="$(git rev-parse --show-toplevel)/mini-harness/bin/mh-changes"
"$_MH" || echo "MH_CHANGES: 없음 — 설치가 깨졌다"
```

**스크립트를 못 찾으면 네가 직접 세지 마라.** 설치가 깨졌다고 사용자에게 알리고,
꼭 진행해야 하면 숫자 없이 판단만 하되 "스크립트 없이 진행했다"고 밝힌다.

마지막 줄이 `MH_CHANGES_OK` 인지 확인한다. 없으면 스크립트가 중간에 죽은 것이다 —
숫자를 믿지 말고 사용자에게 알린다.

`ERROR: git 저장소가 아니다` 면 여기서 멈춘다.

## 1. 막아야 하는가 (판단 1)

`SECRET_SUSPECT` 가 0 이 아니면 **다른 모든 것에 앞서 이것부터 보고한다.**

```
SECRET_LINES 에 나온 파일을 읽고, 진짜 비밀인지 플레이스홀더인지 판단한다.
  진짜다     → 커밋하지 말라고 말한다. .env 로 빼는 방법을 제시한다.
  아니다     → 왜 오탐인지 한 줄로 말하고 넘어간다.
```

스크립트는 값을 출력하지 않는다(`<값 생략>`). **너도 출력하지 마라.**
파일 이름과 변수 이름까지가 보고 범위다.

## 2. 커밋을 나눠야 하는가 (판단 2)

`TOUCHED_TOP_DIRS` 에 서로 관계없는 디렉터리가 섞여 있으면 나누자고 제안한다.

```
auth/ 만                     →  한 커밋
auth/ + docs/                →  한 커밋 (기능 + 그 문서)
auth/ + billing/ + scripts/  →  나눈다. 나중에 되돌릴 때 통째로 되돌아간다
```

기준은 개수가 아니라 **"이 중 하나만 되돌리고 싶어질 수 있는가"** 다.
줄 수가 많다고 나누는 게 아니다. 리팩터링은 500줄이어도 한 커밋이다.

## 3. 정리할 게 있는가 (판단 3)

- `NEW_DEBUG_PRINT` 가 0 이 아니면 → 해당 줄을 찾아 보여주고, 의도한 로그인지 묻는다
- `NEW_TODO` 가 0 이 아니면 → 새 TODO 를 나열한다. 지우라고 하지 마라, 알리기만 한다
- `TEST_FILES_CHANGED` 가 0 이고 `INSERTIONS` 가 50 이상이면 → 테스트 없이 가는 게
  맞는지 한 번 묻는다. **묻기만 한다.** 테스트를 지어내서 쓰지 마라

## 4. 커밋 메시지 초안

한 줄 제목 + (필요하면) 본문. 제목은 **무엇을 왜** 바꿨는지 쓴다.

```
❌  fix: 버그 수정                     무슨 버그인지 6개월 뒤에 모른다
❌  update database.py                 파일명은 diff 를 보면 안다
✅  회의록 업로드가 24시간 뒤 만료되도록 수정
✅  gather() 를 create_task 에 직접 넘기던 버그 수정
```

`git log --oneline -10` 으로 **이 저장소의 기존 스타일을 먼저 본다.**
접두사를 쓰는 저장소면 쓰고, 한국어로 쓰는 저장소면 한국어로 쓴다.
네 취향이 아니라 저장소의 관습을 따른다.

## 5. 보고

이것만 보고한다. 스크립트 출력을 그대로 다시 붙여넣지 마라.

```
막을 것:   (있으면) 비밀키 후보 — 파일과 변수명
나눌 것:   (있으면) 이렇게 나누자는 제안
확인할 것: (있으면) 디버그 출력·TODO·테스트 없음
메시지:    커밋 메시지 초안
```

없는 항목은 줄을 아예 빼라. "비밀키: 없음" 같은 줄은 읽는 사람의 시간을 쓴다.

## 하지 말 것

- **커밋을 직접 실행하기.** 이 스킬의 산출물은 초안이다. 실행은 사용자가 한다
- 스크립트가 준 숫자를 다시 세기
- 비밀키의 **값**을 출력하기 (파일·변수명까지만)
- 테스트가 없다고 테스트를 지어내서 쓰기
- `git status` / `git diff` 를 다시 부르기 — 필요한 건 이미 다 받았다.
  단, 특정 파일의 내용을 판단해야 할 때는 그 파일만 읽는다
